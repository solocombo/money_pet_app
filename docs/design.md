# 記帳養寵物 APP 設計文件

> 最後更新：2026-05-22

---

## 一、核心概念

**APP 名稱：錢寵（暫定）**

透過遊戲化（Gamification）機制解決使用者因枯燥而放棄記帳的問題。  
核心循環：**記帳 → 獲得道具 → 照顧寵物 → 獲得成就感 → 持續記帳**

一句話定位：**「記帳養寵物，省錢換獎勵」**

### 目標受眾
```
核心受眾（18–35 歲）
  → 大學生：第一次自己管錢，需要引導
  → 社會新鮮人：開始有收入，想養成記帳習慣
  → 養成遊戲愛好者：被寵物系統吸引

定位：「想養成記帳習慣但一直失敗的年輕人」

潛在受眾
  → 中年人不太會被寵物系統吸引
  → 但若子女推薦，可能會使用資產統計功能
```

## 二、技術棧

| 項目 | 選擇 | 備註 |
|------|------|------|
| 框架 | Flutter | 一套程式碼同時出 iOS / Android |
| 本地儲存 | SQLite + SQLCipher | 主要資料庫，SQLCipher 負責加密 |
| 備份 | CSV + JSON → Google Drive | 使用者自己的雲端，開發者零成本 |
| 登入 | Google Sign-In | 僅用於取得 Drive 權限 |
| 動畫 | Rive 或 Lottie | MVP 先用靜態圖片 |
| 本地通知 | flutter_local_notifications | 帳單提醒、資產更新、每日簽到 |
| 全體推播 | Firebase Cloud Messaging（FCM） | 公告、活動、優惠情報，免費 |
| 後端 | 無（FCM 除外） | 純本地，隱私優先 |
| 社群功能 | 未來再議 | 預留 UUID 設計即可 |

### 備份策略
- 帳務資料 → CSV（方便使用者在 Excel 查看）
- 遊戲狀態 → JSON（寵物狀態、背包、獎勵櫃）
- 兩者定期同步到使用者的 Google Drive

## 三、功能清單

### MVP 必要功能
- 基本記帳（新增 / 刪除 / 類別）

- 本地 SQLite 儲存
- Onboarding 流程
- 新手任務、每日簽到、每日戳寵物
- 固定任務：每三天更新一次資產資訊

### 之後疊加
- 食材合成系統
- 商店 / 金幣
- 寵物進化
- 預算暴擊（月底省錢雙倍 PT）

- Google Drive 備份

## 七、寵物系統

### 六種屬性值
| 屬性 | 說明 | 自然下降？ |
|------|------|-----------|
| 飽食值 | 飲食類消費提升 | ✅ |
| 健康值 | 健康類消費提升 | ✅ |
| 整潔值 | 生活類消費提升 | ✅ |
| 心情值 | 娛樂 / 人情類消費提升 | ✅ |
| 智慧值 | 學習類消費提升，部分可轉換提升 San 上限或恢復速率 | ❌（只增不減） |
| 理智值（San）| 各動物初始值不同，失控時全屬性下降 | 依事件觸發 |

### 智慧值解鎖系統
| 等級 | 範圍 | 解鎖內容 |
|------|------|---------|
| Lv1 | 0–20 | 基本戳戳、摸頭 |
| Lv2 | 21–40 | 餵食動畫升級、寵物主動跑來找你 |
| Lv3 | 41–60 | 寵物學會把戲（握手／翻滾）、解鎖寵物日記 |
| Lv4 | 61–80 | 寵物幫你找隱藏道具、解鎖特殊合成配方 |
| Lv5 | 81–100 | 寵物進化形態解鎖、特殊互動動畫 |

### 寵物種類
| 類型 | 說明 |
|------|------|
| 基本款 | 貓、狗、狐狸、鳥（新手預設選項） |
| 拼接款 | 類寶可夢混合生物（養成解鎖，與消費人格掛鉤） |
| 惡搞款 | 炸蝦等隱藏角色（隱藏成就解鎖，社群爆點） |

### 生病系統
- 單一類別超支超過閾值（預設 20%）→ 觸發對應生病狀態
- 超過半數類別同時超支 → 當月無法獲得任何 PT
- 生病持續數天後自動康復，或用道具治療

### San 值（理智值）系統

**初始值**
- 依動物種類不同，給予不同的初始 San 值
- 選寵物時作為額外策略考量（例如：貓高、狐狸中、鳥低）

**San check 觸發條件**
```
高機率觸發：
- 單筆消費超過設定金額（衝動消費）
- 深夜記帳（凌晨 12 點後）
- 同一類別當天記超過 N 筆
- 月底預算快見底但還剩很多天
```

**San 值提升方式**
- 智慧值累積到一定程度可部分轉換，提升 San 上限或恢復速率

**失控效果（低調克蘇魯風，無閃爍強烈特效）**
```
視覺層面：
  → 部分 UI 文字變亂碼
  → 寵物動作凍結，只剩呼吸待機
  → 寵物眼神空洞（換靜態圖）
  → 背景輕微去飽和度（變灰）

功能層面：
  → 全部屬性值緩慢下降
  → 商店、合成等功能暫時無法使用
  → 觸發臨時任務（如「連續記帳 3 天讓寵物恢復理智」）
```

**無障礙設計原則**
- 無閃爍、無強烈特效
- 靜靜地壞掉，比大特效更有克蘇魯感

多餘道具 → 換金幣 → 商店買其他道具
```

### 商店機制
- 每日隨機限定商品，增加每天開 APP 的動機

---

### PT 值與獎勵櫃

### PT 計算（兩層）
```
類別層：每個類別各自結算
  實際花費 < 預算 → 省下部分轉換成 PT

總額層：整體預算再結算一次
  兩層都省到 → 雙重獎勵
```

### 完整 PT 獲取機制
| 來源 | 換算方式 | 備註 |
|------|---------|------|
| 類別層省錢 | 省下金額 × 0.1 | 保留小數後一位 |
| 總額層省錢 | 省下金額 × 0.1 | 兩層都達成為雙重獎勵 |
| 收入記帳 | 收入金額 × 0.01 | 全部收入類型都算 |
| 消費省下金額 | 填入金額 × 0.1 | 信用卡回饋、折扣、點數折抵等 |
| 財務目標完成 | 使用者自訂 | 自己設定目標自己決定值多少 |
| 預算暴擊（未來）| 月底雙倍加成 | 省超過預算時觸發 |

### PT 換算
```
1 PT = 10 金幣（單向，PT → 金幣，不可反向）
```

### 預算暴擊（未來功能）
- 月底結算省超過預算 → 雙倍 PT 加成

### PT 用途
| 用途 | 說明 |
|------|------|
| 換金幣 | 1 PT = 10 金幣，單向轉換 |
| 獎勵櫃 | 兌換使用者自訂的現實獎勵 |

### 獎勵櫃
- 使用者自訂現實獎勵（如「吃大餐」、「買遊戲」）
- Onboarding 時強制設定至少一個
- 參考範例：小獎勵 500 PT、中獎勵 1500 PT、大獎勵 5000 PT

## 十、任務系統

### 新手任務（一次性，獎勵金幣或道具）
- 建立寵物
- 設定第一個獎勵櫃目標
- 記第一筆帳
- 累計記帳 7 天
- 第一次使用合成
- 建立第一個財務目標

### 每日任務（獎勵金幣或道具，不給 PT）
- 簽到
- 戳寵物互動（隨機反應：翻身、打噴嚏、跑開等）
- 記至少一筆帳 或 本日無支出打卡

### 本日無支出
```
點擊本日無支出
  → 完成每日記帳任務
  → 飽食值只下降一半（-7 而非 -15）
  → 給少量金幣獎勵
  → 不計入省錢 PT 計算
```

### 財務目標任務（核心功能，給 PT）
```
使用者自訂：
  → 目標名稱（如「這週自己帶便當三次」）
  → 期限（本週 / 本月 / 自訂日期）
  → PT 獎勵金額（自己決定）
  → 完成後手動打勾領取 PT

設計原則：
  → 自己承諾、自己定價，完成動力更強
  → 只限財務相關目標，維持 APP 定位
```

### 里程碑任務（未來功能，獎勵金幣或道具）
- 連續記帳 7 / 30 天
- 累計記帳 100 筆
- 第一次兌換獎勵櫃

## 十一、數值設計

### 屬性值
```
上下限：0–100

自然下降速率（每 24 小時）：
  飽食值  → -15（最快，吃飯最日常）
  心情值  → -10
  整潔值  → -8
  健康值  → -5（最慢，健康是長期的）
  智慧值  → 不下降
  San 值  → 依條件觸發，不自然下降

本日無支出時：
  飽食值只下降一半（-7）
  其餘屬性正常下降
```

### 道具系統
```
每筆記帳 → 隨機獲得一個食材道具
金額大小不影響道具品質（避免鼓勵消費）

道具稀有度與掉落機率：
  普通（灰）  → 60%
  稀有（藍）  → 25%
  史詩（紫）  → 12%
  傳說（金）  →  3%

圖鑑：
  記錄所有曾經獲得過的道具
  未獲得的顯示剪影
  製造收集驚喜感
```

### San 值
```
各動物初始值：
  貓    → 80（高冷，天生淡定）
  狗    → 60（熱情，容易受刺激）
  狐狸  → 70（聰明，中等穩定）
  鳥    → 50（敏感，最容易失控）

失控門檻：San 值低於 20
警戒區間：20–40

San 值下降條件：
  任一屬性低於 30   → -3 / 天
  寵物處於生病狀態  → -5 / 天
  San check 失敗    → -10（即時）
  多個條件同時觸發  → 取最大值，不疊加（避免雪崩懲罰）

San check 觸發條件：
  單筆消費超過設定金額（衝動消費）
  深夜記帳（凌晨 12 點後）
  同一類別當天記超過 N 筆
  月底預算快見底但還剩很多天
```

### PT 換算
```
省下金額 × 0.1 = PT（保留小數後一位）
收入金額 × 0.01 = PT
消費省下金額 × 0.1 = PT
1 PT = 10 金幣（單向）
```

## 十二、Onboarding 流程

```
第一步：歡迎畫面
  → 一句話介紹概念
  → 按下開始

第二步：建立寵物
  → 輸入寵物名字
  → 選擇外觀（MVP 先給預設選項）
  → 寵物做出歡迎動作

第三步：設定獎勵櫃
  → 說明 PT 值概念
  → 強制設定至少一個現實獎勵

第四步：設定預算（可跳過）
  → 詢問是否設定本月預算
  → 可在設定裡之後調整

第五步：記第一筆帳（引導式）
  → 手把手引導
  → 看到道具掉落動畫
  → 看到寵物反應

第六步：完成！
  → 顯示新手任務清單
  → 寵物揮手歡迎
```

**原則：整個流程不超過 3 分鐘，能跳過的讓使用者跳過。**

## 十五、通知系統詳細說明

### 本地通知（flutter_local_notifications）
完全不需要網路，概念像手機鬧鐘——APP 設定好時間，手機自己在時間到時跳出通知，不經過任何伺服器。

```
適用場景：
  → 帳單到期提醒
  → 資產三天未更新提醒
  → 每日簽到提醒
  → 信用卡繳款提醒
```

### 全體推播（Firebase Cloud Messaging，FCM）

**運作原理**
```
APP 第一次啟動
  → FCM 套件自動聯繫 Firebase 伺服器
  → Firebase 產生唯一 token 給這台手機
  → token 存在手機本地（FCM 套件自己管理）
  → 不需要你的後端介入
```

**主題訂閱機制**
```
APP 啟動後，程式碼執行一行：
  FirebaseMessaging.instance.subscribeToTopic('all_users')

FCM 套件拿著本地 token
  → 自動去 Firebase 登記訂閱
  → Firebase 自己維護清單：
    all_users 主題 → [token1, token2, token3...]

推播時：
  你發訊息給 Firebase
  → Firebase 查清單
  → 推送給所有訂閱的手機
  → 完成，你完全不需要碰 token
```

**重要說明**
- token 清單由 Firebase 自動管理，開發者不需要也看不到個別 token
- Firebase 只充當「廣播站」，不存任何財務或個人資料
- 免費額度對個人開發者幾乎用不完

```
適用場景：
  → 新功能公告
  → 信用卡優惠情報更新
  → 節慶活動通知
```

### 通知設計原則
- 允許使用者自訂通知頻率（避免被檢舉騷擾）
- 不在深夜（22:00–08:00）推送全體通知
- 深夜記帳行為本地偵測即可，不需要推播

## 十六、資安與上架規範

### SQLCipher 資料加密

**為什麼需要加密？**
一般 SQLite 資料庫如果手機被備份到電腦，或手機被 root，財務資料可以直接用任何 SQLite 工具打開查看。SQLCipher 在 SQLite 外加一層密碼鎖，沒有金鑰就算拿到檔案也看不到內容。

**使用者體驗**
```
使用者：完全無感，不需要自己輸入密碼
金鑰產生：APP 第一次啟動時自動產生
金鑰存放：手機安全儲存區（Android Keystore）
```

**建議從一開始就加入**，之後才加會需要處理資料遷移，比較麻煩。

### 其他資安規範
- 所有網路請求使用 HTTPS（Google Drive API、FCM）
- 不在 log 中印出任何財務資料
- Google Sign-In 使用官方套件，不自己處理 token

### Google Play 上架

**費用**
- 一次性 25 美金（約 800 台幣），終身有效
- 之後上架任何 APP 或更新都不需要再付費
- Apple App Store 則是每年 99 美金

**必要準備**
```
隱私權政策頁面（必要）
  → 說明收集哪些資料
  → 說明資料存在本地裝置
  → 說明不分享給第三方
  → 說明使用者如何刪除資料
  → 可用 GitHub Pages 或 Notion 公開頁面製作，不需架伺服器
```

**審查風險評估**
| 項目 | 風險等級 | 處理方式 |
|------|---------|---------|
| 財務類 APP 審查較嚴 | 中 | 準備完整隱私權政策 |
| 信用卡優惠情報頁 | 低 | 只放外部連結即可，若未來接付費合作需揭露廣告關係 |
| San 值亂碼效果 | 中 | 在說明文件寫明是遊戲機制，加入「關閉遊戲效果」設定選項，確保亂碼不影響核心記帳功能 |
| 通知頻率 | 低 | 讓使用者自訂通知頻率 |
| 純本地儲存 | 無（加分） | 在說明頁強調隱私優先定位 |
| 沒有自動扣款或訂閱 | 無 | 不需處理 |

**建議上架流程**
```
1. 先用 Google Play 內部測試功能
   → 邀請少數人測試
   → 就算審查有問題也不影響公開版本
   → 修正後再正式上架

2. 正式上架前確認：
   → 隱私權政策頁面已公開
   → SQLCipher 加密已啟用
   → San 值效果有關閉選項
   → 通知頻率可自訂
```

## 十九、系統測試計畫

### 開發中順手做（單元測試）
```
一定要測的計算邏輯：
  → PT 換算是否正確（小數點後一位）
  → 屬性下降速率是否正確
  → 預算超支百分比計算
  → 信用卡額度警戒觸發
  → San 值下降條件觸發
  → 道具稀有度掉落機率分佈

邊界測試（極端情況）：
  → 屬性值到 0 時不繼續下降
  → PT 值為 0 時無法兌換
  → 金幣不足時無法購買
  → 預算未設定時 PT 計算跳過
  → 本日無支出與當天已有記帳同時存在
```

### 上架前做（整合測試）
```
主要流程跑通：
  → Onboarding 完整流程
  → 記帳 → 道具掉落 → 背包 → 使用道具 → 屬性提升
  → 省錢 → PT 計算 → 獎勵櫃兌換
  → 帳單到期 → 通知 → 一鍵記帳
  → 資產更新提醒觸發
  → San check 觸發與失控流程
  → Google Drive 備份與還原

裝置相容性：
  → Android 不同版本（至少測 Android 10、12、14）
  → 不同螢幕尺寸（小螢幕手機、平板）
```

### 使用者測試（上架前一至兩週）
```
找 5–10 位朋友試用：
  → 涵蓋不同年齡和記帳習慣
  → 觀察他們卡在哪裡
  → 收集「看不懂」的地方
  → 特別注意 Onboarding 流程是否順暢

Bug 回報機制：
  → 建立簡單的 Google 表單讓測試者回報
  → 記錄裝置型號、Android 版本、重現步驟
```

### 不需要做
```
→ 自動化 UI 測試（太花時間，個人專案不划算）
→ 壓力測試（純本地架構不需要）
